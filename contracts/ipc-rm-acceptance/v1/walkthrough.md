## Expected corrections and failures

`cases.json` provides each concrete input, shape-validity flag, expected current server facts and result example. These examples are not a simulated authorizer/receiver and prove no enforcement of server facts.

| Attempt / facts | Expected observable result |
| --- | --- |
| No source field/documentation | `missing-source`: 422 field/transport rejection, no acceptance; goods outside usable stock while source is resolved. |
| IPC lacks current approval, independent count or required signatures | `invalid-source`: 409 blocked; no baseline/posting. A signed file alone is insufficient. |
| Source in another chapter, invisible/unknown source or revoked/provider-only authority | `forbidden`: same redacted 403; no cross-chapter existence/ID details. Current authorization checked even after screen review. |
| Persisted RM line belongs to another visible IPC or names another variant | `wrong-parent` / `wrong-variant`: 409, no effects despite plausible quantities/IDs. Full typed tuples must fail both application checks and database constraints. |
| Evidence validating, unavailable or changed immutable version | `unready-evidence`, `missing-evidence`, `changed-evidence`: 409, preserve input and obtain/reconcile valid authorized evidence. No mutable latest-file replacement. |
| New key for already posted source, or a second IPC/RM in the chapter | `duplicate-baseline`: 409; fence/source effects cannot be bypassed. Later discoveries/corrections use approved ADJ. |
| Stale row or changed material | `stale-row` / `stale-material`: 409 with authorized current state. Preserve draft; review actual progress versus affected reapproval/evidence. |
| Same key, changed version/evidence/material fingerprint | `changed-key-payload`: 409; no second posting. Resolve the original attempt first. |
| Unsupported piece precision | `invalid-quantity`: blocked with field feedback; do not round to make the source fit. |
| Lost response with absent terminal result / lookup down | `lookup-no-terminal` / `lookup-unavailable`: uncertain, no failure claim. Later authorized `replayed` returns exactly the saved result. |
