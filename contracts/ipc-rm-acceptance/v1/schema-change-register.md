# Opening schema integration reservations

Revision 1.0.0-review.1, Leader integration handoff. These are **ordered design reservations**, not timestamped Laravel migrations or a claim of implemented tables. Confirm the actual migration names/engine/runtime at P01/P02–P06 integration. No domain DDL belongs in the initial P01 health/session/job migration merely to resemble the full schema catalogue. Every required constraint below must be installed and verified before its consumer can be enabled; absent dependencies keep posting disabled.

| Order / package | Owning responsibility | Reserved dependency and enablement gate |
| --- | --- | --- |
| 00 / P01 | Leader platform | Intended MySQL runner, health and supported session/job adapters only. No IPC/RM, lots or opening seeds. Clean initial migrations prove the runner, not P06 integrity. |
| 10 / P02 | Access / Leader | users, chapters, membership/duty/attribution authority roots, chapter control guards and effective policy roots. Stable chapter guard exists even before any opening row. Resolve bootstrap cycles as below. |
| 20 / P03 | Documents shared records / Leader | operations/results, records/record_lines, immutable record_versions, review requirements/decisions, audit and durable task/outbox primitives; chapter/kind/line/version keys. |
| 30 / P04 | Documents evidence / Leader | private evidence metadata, immutable object identity, bindings and version-pinned associations; no upload posts stock. Full material/evidence FK cycle closed before consumers. |
| 40 / P05 | Inventory / Glenn catalog, Efren ledger | units/variants, approved item policies, location/custody/conditions, restrictions, variant guards, nonposting ledger/projection structures. Reserve cross-module source/lot FK expansion for 50/60. P05 only enables authorized CRUD/queries with zero stock. |
| 50 / P06 source | Purchasing/Receiving / Leader | IPC/count participants, inspected RM/receipt lines/discrepancies, minimal typed CUTOVER linkage and chapter opening fence. Create source keys before dependent lots/movements; no P26 obligations/import implementation is implied. |
| 60 / P06 Inventory | Inventory / Efren, Leader coordinates | lots, acceptance facts, positions/postings/movements and source/evidence/variant FKs; all deferred/cyclic constraints and uniqueness closed. Source, ledger and projection integration becomes one reviewed migration chain. |
| 70 / P06 verification | Leader with Glenn/Efren review | Validate complete DDL on pinned intended MySQL, required failure/race/rollback cases and migration-order/restart checks. Only then enable the real opening operation. Gate 1 functional evidence remains distinct from live activation. |

Order expresses prerequisites; it does not assign Efren's posting or Glenn's queries to Leader. Keep one shared register; additive branches reserve names/order through integration rather than colliding timestamp guesses. Restrictive FKs/append-only history follow schema profiles, with identical target/child types, signedness, ASCII/binary collation and explicit child indexes. No cascading deletion of operational history. IDs use BIGINT UNSIGNED, quantities/costs DECIMAL(20,6), UTC DATETIME(6), versions INT UNSIGNED, hashes BINARY(32); posted PHP money (when applicable) is DECIMAL(20,2).

## Required keys, relations and source guards

| Relationship | Required enforcement before P06 |
| --- | --- |
| Typed headers | `records U(chapter_id,id,record_kind)`; IPC/RM/CUTOVER fixed-kind typed headers reference that full tuple. A registry row without its valid typed source cannot authorize posting. |
| Typed lines | `record_lines U(chapter_id,record_id,id,line_kind)`; IPC/RM lines reference chapter/parent/id/fixed kind plus their typed parent. IPC and receipt lines each expose `U(chapter_id,record_id,id,variant_id)`. |
| Material | `record_versions U(chapter_id,record_id,material_version)`; current pointers, decisions/requirements and `inventory_postings(source_record_id,source_material_version)` reference the full chapter/record/version tuple. Preserve previous version within the same record. Owning operation verifies the canonical full typed content/hash. |
| RM opening source header | Exactly-one source CHECK: `opening` requires non-NULL IPC and source_record_id=ipc_id; PO, supplier delivery and DA columns are NULL. `purchase` later requires approved PO+its supplier DR, `donation` DA; no source-free or mixed alternative. Composite FK to typed IPC; expose header `U(chapter_id,id,ipc_id)` and source kind/identity tuple. Future alternatives cannot be enabled without their typed keys/FKs. |
| RM opening source line | Non-NULL `ipc_id,ipc_line_id,source_record_id,source_line_id`; CHECK source_record_id=ipc_id, source_line_id=ipc_line_id and all nonopening typed source columns NULL. FK `(chapter_id,record_id,ipc_id)` → RM header `(chapter_id,id,ipc_id)`; FK `(chapter_id,ipc_id,ipc_line_id,variant_id)` → IPC line `(chapter_id,record_id,id,variant_id)`. Match header source_kind too, via a strengthened tuple or equivalent fixed opening discriminator check. A generic record_lines FK alone is insufficient. |
| Source dimensions | Chapter/variant, stock location and custody assignment FKs; custody `(chapter_id,id,location_id)`; condition catalogue and restriction-version chapter keys. Locations/condition/valuation/restrictions must match the signed count and inspection or have an authorized material revision/resolution; operations cannot silently substitute them. |
| Inspection quantities | Nonnegative exact decimal CHECKs: delivered=accepted+rejected+held; nonusable_recorded≤rejected+held. In the first complete opening slice, locked operation also checks expected=counted and delivered+missing=expected, unique source coverage, approved scale and cumulative source limits. Cross-row sums are not pretended to be row CHECKs. |
| Discrepancies | `(chapter_id,rm_id,receipt_line_id)` → receipt line parent tuple; preserve kind/qty/reason/resolution/evidence. An open damage exception can coexist with accepted stock and locked baseline. No missing quantity becomes a balance. |
| Count signatures and policy | Count participants/evidence binding refer to the same chapter and IPC record; decisions refer to exact source material/required approval step/policy. Actual distinct identities, required signer set, cutoff/readiness and effective policy remain named locked operation checks. No role-count shortcut. |
| Evidence material pin | Base evidence_bindings has record/optional line/hash/object version but no material-version column. **Reserve an append-only `evidence_material_pins` association** owned by Documents: `(chapter_id,binding_id,record_id,material_version,material_hash)`, unique binding/material association, FK binding `(chapter_id,id,record_id)`, FK `(chapter_id,record_id,material_version)` to record_versions (hash checked against immutable row by consumer). Association is inserted with authorized binding; P06 may not consume a binding lacking this persisted pin. Optional line FK includes its parent; require purpose/target match server-side. This is a proposed additive integration definition, not an existing migration. |
| Immutable byte pin | Actual evidence object exposes chapter/id/content_hash/object_version identity; binding's bound_hash/version refers to the exact tuple, with binary storage-version equality. Scope, readiness, availability, signatures and authorized intended record are also checked by Documents under commitment locks. |
| Opening fence | `chapter_openings U(chapter_id)` and `U(chapter_id,ipc_id)`; FKs to IPC, typed CUTOVER and operation, all chapter-scoped; retain posted time and snapshot_hash. Fence and all opening effects commit together. Existing chapter guard serializes absent fence; UNIQUE is final defense. Every entry path checks the same fence. A second draft IPC is allowed but cannot become a second posted baseline. |
| Source effect identity | `inventory_postings U(chapter_id,source_record_id,action_code,source_batch_key)` **and** generated `single_effect_source_id` for `rm_accept`/`rm_nonusable_intake` with `U(chapter_id,single_effect_source_id,action_code)`. Source is the immutable RM, not IPC registry-only or arbitrary request key. Batch key is server-derived `rm:<RM-id>:material:<material-version>` (fits 64 ASCII bytes); same RM/action cannot post again even with another material/key/batch. |
| Posting and movement | Accepted posting action `rm_accept`, nonusable custody posting action `rm_nonusable_intake`; both join the same owner operation. Movements use positive qty and `receipt` kind into the appropriate usable/nonusable position; nonusable does not create accepted supply. Posting `(chapter_id,id,source_record_id)` → movement source, and `(chapter_id,source_record_id,source_line_id,variant_id)` → receipt line tuple. Evidence binding `(chapter_id,id,record_id)` has record_id=RM. Keep IPC signatures pinned as separate source evidence. |
| Lot origin | `stock_lots U(chapter_id,rm_id,receipt_line_id,lot_kind)`; FK full RM/line/variant. `origin_kind=rm` requires RM parent/line and NULL gain-ADJ pair; later ADJ gain is the other exclusive alternative. Accepted_qty=documented_qty for accepted lots, accepted_qty=0 for nonusable. Positive documented qty; zero effects omitted. Never edit an accepted lot to receive another batch. |
| Positions and endpoints | Lot `(chapter_id,id,variant_id)`; position `(chapter_id,id,variant_id,lot_id)` plus unique non-NULL dimensional `(chapter_id,lot_id,location_id,custody_assignment_id,condition_code)`. Movement endpoints reference full variant/lot tuple, not just position ID. Initialize guarded empty position once; stock projections reconcile to immutable positive movements. |
| Initial acceptance fact | `lot_acceptances` chapter/RM/line/lot tuple and source_batch uniqueness; initial accepted qty mirrors initial lot receipt once, never a second movement/quantity. Nonusable has no accepted fact until a later authorized ADJ treatment for locked opening stock. |
| Durable outcome | `operations U(chapter_id,action_code,idempotency_key)` with canonical fingerprint and authorized saved result; actor/version/evidence audit and durable tasks reference same chapter/operation. Stable task deduplication prevents refresh/follow-up retry from duplicating business effects. |

For nullable alternatives, apply all-or-none CHECKs. Every selected FK tuple has **all components non-NULL**; otherwise MySQL may skip the composite context check. Later PO/DR and DA alternatives preserve their exact typed parent/line/variant relationships and cumulative acceptance; no acceptance route is enabled using a nullable generic source pair alone. Source restrictions and schema proposal details remain preserved.

## Deferred and cyclic constraints

MySQL foreign keys are immediate; this handoff uses **ordered additive DDL**, never transaction-deferred checks or accepted `FOREIGN_KEY_CHECKS=0` data. Examples needing deliberate ordering:

1. Users/chapter/membership/attribution bootstrap, policy approval CONFIG and record/operation references: create target tables and UNIQUE keys first, then add FKs after the full graph exists. Where null is a legitimate pre-submission state, insert draft registry/operation, attribution/version/typed rows and set the current pointer within the same operation. Do not weaken required final attribution/version fields to break a cycle. If a non-NULL insert cycle remains, redesign the relationship before enablement.
2. `records.current_material_version` ↔ `record_versions.record_id`: create records with the legitimately NULL pre-submission current pointer, create snapshots and add the current-version FK; submission sets the pointer atomically. Self previous-version FK is same-record and append-only.
3. Version-pinned evidence binding ↔ signed record material: material snapshot excludes self-referential signature bindings; publish the immutable material first, then bind ready evidence and insert material pin. Complete evidence target/line/version/object FKs before P04/P06 consumption. Preserve historical pins on revision.
4. RM/source ↔ lot/receipt `existing_nonusable_lot_id` ↔ Inventory movement endpoints: create IPC/RM source parents/lines, then lots/positions/postings/movements, then add the forward existing-lot FK. That optional field stays NULL for this first intake. P05 cannot post source-free stock while the source graph is incomplete.
5. `chapter_openings` → CUTOVER/IPC/operation: reserve a minimal typed CUTOVER parent and opening snapshot at P06 rather than omitting its non-NULL reference until P26. Full import/payment/PO/custody carry tables remain P26. No demo import or synthetic historical receipt is required.

Before enabling each consumer, enumerate expected constraints/indexes from the migration expansion, inspect intended-MySQL metadata, exercise wrong chapter/parent/line/variant/source insert failures, and run commit-time cumulative/authority/evidence checks through the real owner. Verify a failed cyclic constraint migration leaves the operation disabled and an additive repair path; do not silently skip FKs on restart. Verify duplicate baseline/source/key races in both orderings and rollback failures after every participant/write group. These are **pending P06 evidence**, not checks executed by this contract.
