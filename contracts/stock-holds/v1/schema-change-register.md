# Coverage schema integration reservations

Revision `1.0.0-review.1`. Extend the IPC/RM acceptance contract's [shared ordered register](../../ipc-rm-acceptance/v1/schema-change-register.md); this is not a second migration runner, implemented DDL or a reservation of guessed timestamp filenames. Leader coordinates the single dependency order. Glenn owns query/reservation projections and Efren receipt/physical posting; Access/Documents own shared attribution/records/evidence. Exact DDL must be reviewed together on the intended pinned MySQL before its consumer is enabled.

## Additive tables and key relationships

All chapter-owned keys include `chapter_id`; every tuple component needed for a relationship is non-NULL in that alternative. Use `BIGINT UNSIGNED` IDs, `DECIMAL(20,6)` coordinates/quantities, `INT UNSIGNED` positive versions, UTC `DATETIME(6)`, binary immutable hashes and compatible FK types/collations/indexes under the working schema profiles. Restrictive deletes; no cascading operational-history deletion.

| Reservation | Necessary enforcement |
| --- | --- |
| Existing variant guard extension | One row per `(chapter_id,variant_id)` with current `eligibility_version`; FK to variant. Position `row_version` is distinct. Variant guard serializes all purposes and absent rows; policy/restriction changes share it. |
| `stock_coverage_cells` immutable geometry | PK `(chapter_id,id)`; candidate key `(chapter_id,id,lot_id,variant_id,unit_id)`; lot FK includes chapter/variant and its unit relation; `start >= 0`, `end > start`, `quantity = end-start`. Locked cross-row checks enforce quantum, bounds and disjointness; same-lot overlapping coordinates are forbidden even across positions. No physical quantity comes from cell creation alone. |
| `stock_coverage_splits` + child association | Immutable split operation/source/parent and ordered child IDs. One split per parent via `U(chapter_id,parent_cell_id)`, each child has at most one parent; composite cell FKs enforce identical lot/variant/unit, no self edge. Under guard prove children partition the live parent exactly, prevent cycles/overlap and retire parent atomically. Original receipt/gain roots are the only root-creation paths. |
| `stock_coverage_live` controlled projection | PK `(chapter_id,cell_id)`; non-NULL lot/variant/unit and FK to geometry tuple. Active leaf lifecycle is `stored` or `terminal`; a stored leaf requires current position, a terminal leaf has NULL position and a retained release/consumption event. Retired parent removed only from this projection, never immutable geometry/history. |
| `stock_coverage_events` | Append-only split/assignment/consume/return history with cell/lot/variant/source record+material/line/operation/movement links. Exactly movement-bearing events have the approved source-linked movement; hold-only events have none. Source line FK includes chapter, parent and variant. Terminal consumption and reactivation quantities cannot exceed the original handed-over geometry. |
| Existing `stock_holds` strengthening | Keep ID/source/initial position/reason/opened/released fields as history/projection. Add chapter/variant and finding material pin, opening actor/evidence/operation and row version. Initial position tuple matches chapter/variant; current coverage is authoritative through cells. `held_qty` becomes reconciled per-reason coverage, never independent overlap authority. | `stock_hold_cells` active projection | PK `(chapter_id,hold_id,cell_id)`; reason/variant tuple FK and live cell/variant tuple FK, including chapter. An active link requires an active hold and stored live leaf; validate under locks. Links from two reasons to the same cell are allowed. Cross-lot reasons require explicit compatible provenance, not inferred equal IDs/quantities. Membership changes append events first/atomically; no projection-only repair. |
| `stock_hold_events` + terminal resolution | Append-only opened/inherited/cleared membership history and resolution with original finding, exact source/resolution material versions/hashes, actor attribution, reason, evidence pins, operation/result/audit. `U(chapter_id,hold_id)` on full terminal clearance; FK `(chapter_id,hold_id,variant_id)` to hold. Locked checks enforce whole-cell exact active remainder and homogeneous protection. Header `consumed+released <= qty`, approved demand remaining and total coverage reconciled. No pairwise-link sum may become the aggregate intersection. |
| Query/position aggregates | Controlled read models only, reconcilable to immutable events/movements and exact current cells. Store row/version scope if cached. Fail closed on a mismatch; report an integrity blocker for authorized repair rather than a fabricated zero/positive balance. |

Cells retain an explicit `unit_id` and FK to the lot/variant's unit. A cell source never becomes a generic registry record: its lot already has the IPC/RM acceptance contract's valid typed RM/line/variant or authorized gain-ADJ source. Hold/resolution sources and optional line associations enforce record chapter/parent/material and same target, independently of geometry. A global record FK or a nullable composite missing its required discriminator is insufficient.

## Database constraints versus serialized checks

Geometry row CHECKs, composite FKs, unique parent/child relationships, terminal clearance uniqueness and one-cell reservation ownership are database-enforced. **Cross-row** interval disjointness/complete partition, inherited memberships, active-state consistency and coverage/position sums are mandatory serialized owning-operation checks under the existing variant root, with conditional version updates and complete rollback. All mutation entry points (including import, expiry, correction, restriction changes and jobs) must use that gate; ordinary callers cannot write projections directly. Maintenance repair is fenced, audited and reconciled, never an alternate positive-balance setter. Install the working schema's append-only privileges/triggers before consumer enablement.

Do not claim that a MySQL row CHECK can inspect sibling intervals or sum another table; [MySQL's CHECK rules](https://dev.mysql.com/doc/refman/8.4/en/create-table-check-constraints.html) disallow other-table columns and subqueries. The 8.4 manual is used here to verify constraint semantics, not to select the project's eventual pinned runtime. Implement/test the combined FK/unique/check **and** guarded-operation design on the selected intended MySQL; unchecked application-side preflight alone is insufficient. Runtime integration must demonstrate that there is no writer path omitting the shared guard.

## Cycles, rollout and failure proofs

Create identity/record/operation/evidence roots first, typed source/lot/position keys next, then geometry/live/event and hold projections. A live assignment may need its event while an event points to the cell: create immutable cell, then event, then live pointer in one transaction after both tables/FKs exist; a split similarly creates children/events before replacing the live parent. Event history references immutable cells, not removable live membership. Hold membership links to live cells; replace inherited links before retiring a parent. Drop/insert projection references in FK-safe order inside the same transaction while external readers see only committed state. A terminal clearance links an existing reason/source/material/event; its result pointer can be finalized in the same transaction once the result row exists. Temporary nullable bootstrap pointers may exist only before consumer activation; close required constraints and verify no orphan rows before enablement. MySQL FKs are not assumed deferred to transaction end.

Existing stock, if any in a future deployment, requires a fenced provenance-preserving partition/backfill and reconciliation before switching consumers; unknown overlap stays conservatively blocked. This contract does not authorize a live migration or fabricate coverage from historical reason totals. Fresh P06 stock gets its initial partition with the accepted receipt.

Required intended-MySQL negative checks: wrong chapter/parent/variant/unit/lot/position/source/material, duplicate live cell reservation/terminal clearance, overlapping sibling cells, missing split child/inherited reason, reserved projection drift, unauthorized/unready binding and source-free geometry insertion. Required integrated checks: valid receipt then both race orders, protected commitments, actual quarantine treatment, fault after each provisional write, lost-result lookup and retry. Keep the relevant consumer disabled until those checks pass and actual Glenn/Efren compatibility is recorded. P05/P06 acceptance and P00 completion are not claimed here.
