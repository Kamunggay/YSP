## Package ownership, provider dependencies and verification gates

Provider -> consumer. Contract edges require only the cited reviewed interface, not a complete provider package. Integration/rehearsal edges govern the stated connected completion. Inherited edges retain explicit transitive inputs. Activation edges are later live prerequisites, excluded from the implementation DAG. In particular P26 live activation requires P28, while P28 recovery rehearses P26; this is not a circular implementation blocker.

Each application package requires intended-MySQL integrity, connected real UI/API, current chapter/duty/policy/version checks, branch/retry/negative evidence, traceable history, nonauthor review, green applicable CI, reviewed merge and repeatable demonstration. Critical postings additionally require atomic rollback, duplicate/lost-response lookup and races with real evidence/stock/money participants. Source-row mapping proves none of these execution gates.
